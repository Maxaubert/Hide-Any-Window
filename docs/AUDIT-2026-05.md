# Hide Any Window — Audit (2026-05-23)

Full multi-agent audit of the repo. Findings are grouped by domain. **Waves 1 and 2
have already been applied** (Claude Code tooling + docs, and all build/test-verifiable
C#/XAML fixes — see the git history for this date). This document is the backlog of the
remaining, harder-to-verify work: the AutoHotkey **service** behavior changes (Wave 3)
and the **installer / signing** changes (Wave 4), plus lower-priority polish that was
deferred. Each item lists `file:line`, the problem, and a concrete fix.

> Verification note: the C# changes were verified with `dotnet build` + `dotnet test`
> (12 passing). The items below change service runtime behavior or the installer, which
> cannot be exercised from a build alone — apply them with manual testing on a real
> Windows box (start the service, hide/restore windows, run the installer + uninstaller).

## Wave 3 — Service (AutoHotkey v2) — behavior-changing

### S1 [CRITICAL] Single-instance authority — `main.ahk:2,131-142`
`#SingleInstance Force` (line 2) and the liveness mutex fight each other: `Force` kills the
prior instance when a second launches, so a healthy instance holding hidden windows can be
terminated without its `OnExit` cleanup, and the mutex "already running → exit" branch is
largely unreachable.
**Fix:** change `#SingleInstance Force` → `#SingleInstance Ignore` so the mutex governs
liveness, and capture `A_LastError` into a local *immediately* after the `CreateMutexW`
DllCall (before any other call can clobber it).

### S2 [HIGH] Guard the WinEvent callback — `main.ahk:205-235`
`WinEventCallback` does window queries, hide logic, and file I/O (`SaveHiddenJson`) with no
try/catch and no re-entrancy guard. An exception thrown inside an OS `CallbackCreate`
callback can pop an error dialog in a background service or destabilize the hook; file I/O
can pump messages and re-enter.
**Fix:** wrap the whole callback body in `try { ... } catch as e { ServiceLog("ERROR", e.Message) }`
and add a `static busy` re-entrancy flag that early-returns while a hide is in progress.

### S3 [HIGH] Prune hidden entries on window close — `main.ahk:25`, `registry.ahk:16`
Only `EVENT_OBJECT_SHOW` is hooked. When a hidden target closes/exits, its entry is never
removed from `HiddenEntries`/`hidden.json` (`RegistryRemoveByHwnd` is **dead code**, called
from nowhere). The list grows unbounded, and because Windows recycles HWND values, a stale
stored hwnd can later collide with an unrelated window — restoring or skip-hiding the wrong
one.
**Fix:** also hook `EVENT_OBJECT_DESTROY (0x8001)` and call `RegistryRemoveByHwnd` on
destroy; and/or validate `WinExist` for each entry during the startup scan / restore and
drop dead ones.

### S4 [MEDIUM] Make `hidden.json` writes atomic — `registry.ahk:53-64`
`SaveHiddenJson` does `FileDelete(path)` then `FileMove(tmp, path)`, leaving a window where
`hidden.json` does not exist (the manager can read nothing).
**Fix:** write the temp file then `FileMove(tmp, path, 1)` (overwrite) **without** the prior
delete. Consider debouncing writes since this runs in the hide hot-path.

### S5 [MEDIUM] Don't misclassify already-hidden windows — `hider.ahk:61-84`
`TryHideWindow` uses `IsWindowVisible == 0` as the success signal, but that's also 0 for any
ancestor-hidden window, so a window already hidden by something else gets recorded as our
hide (with a mutated ex-style) and gets force-shown on restore.
**Fix:** capture whether the window was visible *before* the attempt and gate success/record
on that.

### S6 [MEDIUM] COM teardown — `hider.ahk:12-42`
`CoInitializeEx` is never paired with `CoUninitialize`, `TaskbarListPtr` is never `Release`d,
and the `CoInitializeEx` HRESULT is unchecked. Harmless at process exit but a real ref/handle
leak.
**Fix:** check the HRESULT; release the interface and `CoUninitialize` on shutdown.

### S7 [LOW] Diagnostics & misc
- `GetExeBasenameForHwnd` (`main.ahk:60-81`) silently returns "" when `OpenProcess`/
  `QueryFullProcessImageNameW` fail on protected processes → undiagnosable non-hides. Add a
  debug-level log.
- Config reload re-runs `StartupScan` and re-hides windows the user manually un-hid
  (`main.ahk:303-308`) — document this as intended, or track user-restored windows.
- mtime-only change detection is second-resolution (`main.ahk:323`); same-second rewrites are
  missed. Low impact at 1 Hz; consider size+mtime or a hash.
- Name the magic numbers (`0x1000`, `0x2`, vtable indices); prefer `#Warn LocalSameAsGlobal, Off`
  over the project-wide `#Warn All, Off`.

### S8 [TESTING] The riskiest service code is untested
`main.ahk`/`hider.ahk` have **no** tests, and the existing `service/test/*.ahk` are
interactive (`MsgBox`) and run against the **live** `%APPDATA%\HideAnyWindow` files (running
them clobbers a real user's config/log/hidden state).
**Fix:** add non-interactive tests (exit-code only, no MsgBox) that run against a temp
directory, covering at least: `ApplyNewConfig` rule-diff, the self-hide denylist, malformed
`hidden.json` (`registry.ahk:75` catch path), and config edge cases (non-array `rules`,
missing rule keys). A `run-tests.ps1` that runs all of them and aggregates exit codes would
make these CI-able.

## Wave 4 — Build / Installer / Signing

### B1 [HIGH · SECURITY · DECIDED] Stop trusting the dev cert as a Root CA — `HideAnyWindowSetup.iss:49`
The installer runs `certutil -addstore Root` to plant the self-signed `CN=HideAnyWindowDev`
cert as a **trusted root CA** — the strongest trust anchor in Windows — and the matching
`.pfx` is protected only by the public `devpassword`. Anyone who rebuilds (or extracts the
key) can sign binaries this machine trusts as root-issued.

**Decision (chosen):** install to **`TrustedPublisher` only**, not `Root`.
**Fix:**
- In the `[Run]` section, drop the `-addstore Root` step; keep only the `TrustedPublisher`
  install. (UIAccess requires the binary chain to be trusted for the publisher; TrustedPublisher
  is the scoped store for that and avoids machine-wide root trust.)
- The longer-term correct fix is a real Authenticode signature from a recognised CA, which
  removes the need to manipulate local trust stores at all.

### B2 [MEDIUM] Remove the cert by thumbprint, not subject — `HideAnyWindowSetup.iss:71-73`
Uninstall runs `certutil -delstore Root "HideAnyWindowDev"` (subject substring), which can
over-match other certs or, if certutil's match semantics differ, **orphan** the trust anchor.
**Fix:** delete by the cert's **SHA1 thumbprint** (stable, exact). Capture it at build time
or hardcode it since the cert is fixed. (Update both the install and uninstall steps to match
the B1 store change.)

### B3 [LOW] Sign the manager exe too — `build.ps1:130-137`
Only the service exe and the installer are signed; the **manager exe is unsigned** — yet it's
the binary that runs `requireAdministrator` and is launched `/RL HIGHEST` by the logon task.
The trusted cert therefore buys nothing for the main app.
**Fix:** add a `signtool sign` call for the manager exe after publish (or, if you keep it
unsigned, drop the trust step since it isn't providing authenticity).

### B4 [MEDIUM] Make the build headless/CI-able — `build.ps1:36-72`
The build uses `FindWindowEx`/`SendMessage BM_CLICK` to dismiss the Ahk2Exe "Base file
appears to be invalid" GUI dialog — fragile and impossible on a build server.
**Fix:** use Ahk2Exe's CLI/silent options (or a newer Ahk2Exe that doesn't raise the dialog),
then add a GitHub Actions workflow (`.github/workflows/build.yml`) that runs `dotnet build` +
`dotnet test` on push/PR. (The dialog automation is the only thing blocking CI today.)

### B5 [LOW] Build portability & robustness
- Hardcoded tool paths (`build.ps1:8-9,161`) — probe registry/PATH or accept override params.
- Treat `.cert.pfx` + its password as a real secret (env var / secret store), not the
  hardcoded `devpassword`; shorten the cert validity.
- Installer-sign failure is only a warning (`build.ps1:175`) — a "Done" message can print for
  an unsigned installer. Make it loud.
- Record provenance (source URL + commit/hash) for the vendored `service/lib/JSON.ahk`
  (thqby/HotKeyIt v1.0.8) — currently only the file header notes it.

## Deferred polish (low priority, not yet applied)

### Manager backend (C#)
- **SchemaVersion migration** — `Config.SchemaVersion` round-trips but `LoadAsync` never
  inspects it, so there is no real upgrade path. Add a branch in `LoadAsync` when a v2 ships.
- **`Win32` SetLastError** — add `SetLastError = true` to `EnumWindows`/`IsWindowVisible`/
  `GetWindow` for consistency (return values are already used, so low impact).

### Manager UI (XAML)
- **Title-bar drag inset** — `MainWindow.xaml:17` reserves a fixed `140px` for caption buttons;
  this won't track caption-button width across DPI/locale. Set it from
  `AppWindow.TitleBar.RightInset` instead. (Real high-DPI bug, but needs runtime verification.)
- **Status-dot colors** — still set in code-behind (`MainWindow.xaml.cs` `RefreshStatus`).
  Move `StatusRunningBrush`/`StatusStoppedBrush` into the App.xaml theme dictionaries for
  theme-aware contrast. (Wave 2 already moved the picker grays to theme resources.)
- **Mockup chrome** — the mockups define a titlebar bottom border, footer top border, and a
  subtle tile shadow that the implementation omits. Cosmetic.
- **`App.xaml` theme dictionaries** — `Default` and `Light` are byte-for-byte duplicates;
  collapse to `Light`/`Dark` (or make `Default` genuinely high-contrast-aware).

## What was applied in Waves 1–2 (for reference)

**Wave 1 (tooling/docs):** `CLAUDE.md`, `.claude/skills/{build-installer,ahk-service}`,
`LICENSE` (MIT), README Security/Troubleshooting/prereq sections, `.gitignore` `.claude` rule.
(`.claude/settings.json` permission allowlist was *not* written — granting permissions is a
user decision; the recommended JSON is in the session summary.)

**Wave 2 (verified C#/XAML):**
- `ConfigStore`: thread-safe + disposed debounce CTS, `FlushPendingAsync()` for save-on-close,
  `fs.Flush(true)` + `File.Move` retry on lock, corrupt-config backup, `ConfigureAwait(false)`.
- `MainWindow`: `RefreshStatus` no longer `async void` and no longer re-reads config every
  second (kills the read/write race + crash vector); flush-on-close wired; empty state added;
  toggle is now a single-writer (`OneWay` bind) instead of TwoWay + manual resync.
- `ProcessEnumerator`: `EnumWindows` callback wrapped in try/catch (no exceptions across the
  native boundary); image-name buffer grows on `ERROR_INSUFFICIENT_BUFFER`.
- Dead `AlreadyMonitored` machinery removed (was never reachable).
- Accessibility: `AutomationProperties.Name` on the Settings gear, per-row Delete + toggle,
  the autostart toggle; picker count is a live region; secondary text uses theme brushes.
- `RuleViewModel.ServiceRunning` passthrough replaces the fragile cross-element `Binding`.
- `ServiceController`: log de-duplicated to `ManagerLog`; mutex name is injectable so the
  unit test is hermetic. `.csproj`: `LangVersion 12.0`, `TreatWarningsAsErrors`, analyzers,
  dropped x86, removed duplicate `PublishReadyToRun`.
- New tests: `ConfigStoreDurabilityTests` (corrupt backup, flush, supersession), `RuleTests`.
